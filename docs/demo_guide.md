# 🎬 期末 demo 逐段講稿 —— 個人化推薦以後(SECTION 08-10)

這份是給**期末 demo**用的腳本,聚焦「個人化推薦以後」的三段:
**SECTION 08 個人化推薦 → 09 健康日誌 → 10 Agent Bot**,
外加加分亮點「🤖 Agent Bot(聊天平台)**來這裡讀** JSON 回答(拉取模型,不綁特定產品)」。

一句話定位:**儀表板一打開就錨定你的城市(預設聚焦、預警卡置頂);SECTION 08 起
進一步收斂成「給『你這個人』的健康決策」,最後讓 Agent Bot 把它帶進聊天平台(Discord / LINE…)。**

## 0. 事前準備(demo 前 5 分鐘做完)

1. **(選配)灌 SECTION 08 的 demo AQI**(讓「比上週 ±X%」徽章更明顯):
   ```
   python scripts\seed_demo_data.py --city taipei      （= 你要展示的常駐城市)
   ```
   灌入:過去 16 天每小時 AQI + 該城市「污染事件軌跡」(本週升高),標記為 demo、隔離在
   `source='demo'`,demo 後可 `seed_demo_data.bat --clear` 清除。**不跑也行** —— SECTION 08
   會改用真實 CAMS 的近 7 天。

   > 💡 **健康日誌(打卡紀錄)不必灌** —— App 進 SECTION 09 會自動依「你城市當下生效的 AQI」
   > 回填打卡紀錄(跑了上面就對齊 demo、點數較多;沒跑就對齊真實 CAMS,約 7 天)。
   > demo AQI 放在隔離的 `source='demo'`,**中途重跑 Pipeline 不會被覆蓋**。

2. **啟動 App**:雙擊 `run.bat` → 瀏覽器自動開 `http://localhost:8501`。

3. **(建議)填 LLM 金鑰**:sidebar 選一家 LLM 貼 key。有 key → 分析師 / 預警員 / AI
   助理會給「真・個人化文字建議」,demo 最亮眼。**沒有 key 也能 demo**(見第 5 節)。

4. **封面填個人 persona(關鍵:在跑 Pipeline 之前)**:封面「**步驟 ① 個人健康檔案**」
   展開表單,自行填入年齡 / 性別 / BMI / 已診斷疾病(ICD-10)/ 病歷重點 / AQI 閾值
   (demo 建議:台北、72 歲、BMI 24.1、COPD(J44)、AQI 閾值 50)。

5. **跑 Pipeline**:封面點「▶ 啟動三代理人 Pipeline」,等 3 隻 agent 跑完(~10-30s)。
   > 因為 persona 是在「跑之前」填的,分析師 / 預警員**第一次跑就會據此個人化,不必重跑**
   > —— 這正是這版相對上一版的改進。沒填 EPA token 也沒關係,會以 demo / mock 撐起儀表板。

## 1. SECTION 08 · 個人化推薦(主角,花最多時間)

> 注意:個人設定**輸入**已移到封面「步驟①」;SECTION 08 現在是**結果區**。

**開場白**:
> 「前面的儀表板雖然涵蓋全台 20 縣市,但每一區的預設視角都已經錨定在**你的城市**
> (預設聚焦、趨勢圖預設只放你的城市、預警建議跟著你)。對使用者真正重要的是:**我住的地方、
> 我的身體,現在能不能出門?** SECTION 08 就是把這些資料,收斂成『對你一個人』的答案。」

**操作 + 講解**:

1. **(回封面)個人健康檔案**:展開封面步驟①,指出可填 **年齡 / 性別 / BMI /
   ICD-10 已診斷疾病 / 病歷重點 / ⚠ 我的 AQI 閾值 / 上傳病歷**。demo 範例:「台北、72 歲、
   BMI 24.1、COPD（J44）、AQI 閾值 50」。
   > 重點台詞:「我們**不分『五大敏感族群』那種粗分類** —— 而是針對『你這個人』:年齡、BMI、
   > 確診碼、甚至上傳的病歷,一起注入 LLM 與 RAG(個人病歷享 1.4× 加權),讓建議真正為你量身。」

2. **你的城市現況卡 + 7 天趨勢圖**(SECTION 08):台北這 7 天呈現 AQI 起伏,並出現
   「**比上週 ↑/↓**」徽章。
   > 「歷史趨勢與週對比都來自本機 SQLite —— 真實 CAMS;若有跑選配的 demo AQI,則隔離在
   > `source='demo'`,重跑 Pipeline 不會被洗掉。」

3. **🩺 你的個人化健康指數(一張卡,針對你本人)**:以**你的 AQI 閾值**(50)為門檻算
   `safe_hours`(今天還能在戶外多久)+ 防護等級,並把年齡 / BMI / COPD 列為你的檔案資訊。
   > 「這不是『選個族群套公式』—— 是用**你自己**設的閾值 + 你的檔案算的。閾值越低(越敏感),
   > 同樣空品下建議戶外時數越短。公式透明,個人化細節再交給下方 LLM 文字建議。」

4. **(有 LLM key 時)預警員詳細建議**:回 SECTION 07,頂部就是「🩺 預警員 · 給你的詳細建議 —
   {你的城市}」一整份分節建議(現況風險 / 外出建議 / 防護裝備 / 症狀警訊 / 一句總結)。
   **因為 persona 在跑之前就填好,這段第一次跑就有**;點「城市排行」換聚焦後,
   可一鍵「🔁 改為新城市重新產生」(單獨一次 LLM 呼叫,約 10-30 秒,demo 可現場展示)。

## 2. SECTION 09 · 健康日誌(展示「資料閉環」)

**講解**:
> 「個人化不該只是單向建議,而要能驗證『空污到底對我有沒有影響』。SECTION 09
> 讓使用者每天打卡症狀與戶外時數,系統把它和當天 AQI 對齊。」

**操作**:

1. 指出左欄「今日打卡」表單(症狀 0-5 / 戶外分鐘 / 備註),可現場補打一筆今天的。
2. 右欄散點圖:打卡紀錄已由 App 自動回填(依你城市的真實 AQI、不含今天),x = 當日平均
   AQI、y = 症狀分數、泡泡大小 = 戶外分鐘。
3. 重點:系統自動算出 **Pearson r(約 +0.9)** 並給中文解讀(如「✓ 你對空污較敏感」)。
   > 「這是**個人化的證據**:這位使用者的症狀與 AQI 明顯正相關 —— 之後的建議就更有底氣。」

## 3. SECTION 10 · Agent Bot(🌟 加分亮點 · 拉取模型)

**講解**:
> 「最後,讓個人化離開 App、進到聊天平台。但我們**不用 webhook 推、也不產生排程指令** ——
> 而是 Pipeline 跑完把結果匯出成一份 JSON,讓 **任一 agent bot『來這裡讀』**(以 Hermes 為範例)。」

**操作**:

1. **匯出狀態**:SECTION 10 會顯示「✓ 最後匯出:時間 · 20 城市 · 資料模式 · 個人檔案:有」。
   展開「👁 預覽 Agent Bot 會回的內容」,當場看到 bot 會貼的全國概況 + 你城市的建議。
   > 「這份 `agent_export/latest_aqi.json` 就是 Pipeline 剛剛寫的 —— 全台數據 + 分析 + 你的 persona。」

2. **現場 @bot / 本機驗證(很有說服力)**:本機 Hermes 已綁定 Discord 頻道
   (#每日空氣天氣報告),可直接在頻道打 `@bot 台中空氣如何` 現場示範;
   或切到 terminal 跑
   ```
   python agent_skills\aqi-live\read_export.py 台中市
   ```
   印出的繁中內容**就是 bot 會貼進聊天平台的**(含「🩺 給 72 歲、COPD、BMI 24.1 的提醒」)。
   > 「Agent bot 就是呼叫這支(或讀同一份 JSON)。資料是 AgentAQI 預先抓好的,
   > bot 不必自己打 EPA / LLM、不需任何 API key。我這裡用 Hermes 當範例,換成任何會讀 JSON 的框架都行。」

3. **🌟 為什麼是「拉取」+ 不綁產品**:
   > 「推送要架 webhook、註冊 cron、處理失敗重試;拉取只要一份 JSON。Agent bot 與 AgentAQI
   > **解耦** —— 換成別的 bot 框架,也只要會讀這份 JSON 就行。這就是『對接不寫死單一工具』。」

## 6. 可能被問到的問題(預備答案)

- **「這真的有個人化嗎?」**
  → 我們**不分五大敏感族群**(那是粗分類)。個人化建立在你**本人**的檔案:年齡 / BMI /
  ICD-10 診斷 / 病歷 / 你自己設的 AQI 閾值 —— 注入 LLM prompt + RAG 加權,SECTION 09 再用你
  自己的日誌算敏感度,連 Agent Bot 回答都帶你的 persona。

- **「`safe_hours` 怎麼算?憑什麼是個人化?」**
  → 用**你自己設的 AQI 閾值**當門檻:`safe_hours = max(0, 12 - max(0, 當前AQI - 你的閾值) × 0.15)`。
  閾值越低(你越敏感)→ 同樣空品下建議戶外時數越短。公式透明、不靠魔術數字;更細的個人因素
  (年齡 / 疾病)交給 LLM 文字建議。

- **「這些歷史數據是真的嗎?」**
  → **誠實說**:你城市的歷史 AQI 是真實外部 API 抓的(EPA / CAMS / 民生公共物聯網 / LASS);
  健康日誌的「打卡紀錄」(症狀 / 戶外分鐘)是為展示回填的,但**對齊的是真實 AQI**,所以散點
  的正相關是真的。(若有跑選配的 demo AQI,則該段歷史標記為 demo、可 `--clear` 一鍵清除。)

- **「Agent Bot 真的能在聊天平台跑嗎?用哪個?」**
  → **已經在跑**:本機 Hermes 裝了 `aqi-live` skill、以 aqi-reporter 人設綁定 Discord 頻道
  (#每日空氣天氣報告),demo 可現場 `@bot` 示範;`read_export.py` 也能當場印出 bot 回覆
  (見 README『Agent Bot 整合』)。**不綁特定產品** —— 我用 Hermes 當範例,換成任何會讀那份 JSON 的 bot 都能接。

- **「為什麼不用 webhook / cron 推送?」**
  → 推送要架 webhook、註冊排程、處理失敗;拉取只要一份本機 JSON,bot 與 App 解耦、好維護、好換。
  (補充:repo 內 `external/cal-env-watch/` 是組員的「行程**事前預警**」推播模組 — 那是另一個場景:
  行程要到了必須主動講,推播才對;問答場景用拉取。兩者互補不衝突,demo 以本體為主。)
